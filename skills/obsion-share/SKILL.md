# 옵시온으로 공유

사용자가 말하는 **옵시온, 옵시언, Obsion**은 같은 앱이다. 실행 중인 앱에 요청하므로 앱의 공유 기록, 암호화된 기기 키, 로컬 첨부 서버를 그대로 사용한다. 명령은 이 스킬 폴더의 `scripts/obsion-share.cjs`로 실행한다. `node`가 PATH에 없으면 `~/.local/bin/node`를 확인한다.

## 요청 해석

| 요청 예시 | 실행 |
| --- | --- |
| “옵시언으로 공유해줘” | 문서를 읽기 링크로 공유 |
| “옵시언으로 이 파일 첨부해서 공유해줘” | 지정한 파일만 첨부해 공유 |
| “옵시온으로 편집 가능하게 공유해줘. 암호는 1234” | 해당 요청의 암호로 공동 편집 활성화 |
| “옵시온 공유 링크 암호를 5678로 바꿔줘” | 같은 링크의 암호 변경 |
| “옵시언에서 현재 공유중인 페이지 알려줘” | 현재 공개 중인 페이지 목록 조회 |

공유 대상은 현재 요청과 대화에서 특정된 문서 또는 파일이다. 대화에서 만든 글을 공유한다면 그 글만 Markdown으로 저장한다. 보존할 원본이 따로 없는 경우 `~/Documents/Obsion Shares/` 아래에 덮어쓰지 않는 이름으로 저장한다. 첨부만 지정했다면 제목과 다운로드 안내를 담은 짧은 Markdown 페이지를 같은 폴더에 만든다. 대상이 불분명하면 어떤 문서나 파일인지 한 번 질문한다. 작업 폴더 전체나 다른 노트를 함께 공개하지 않는다.

암호는 요청마다 사용자가 지정하는 **숫자 4자리 문자열**이다. `1234`는 예시이며 기본 암호가 아니다. 편집을 요청했지만 암호가 없으면 원하는 4자리 암호를 질문한다. 암호를 생성하거나 기존 암호를 조회했다고 주장하지 않는다.

## 공유하기

공유 요청은 해당 문서의 공개와 명시한 첨부의 공유를 허용한다. 추가 승인 절차를 만들지 말고 미리보기와 범위를 확인한 뒤 실행한다.

1. JSON을 **표준 입력**으로 전달해 `prepare`를 실행한다.

   ```sh
   node <스킬폴더>/scripts/obsion-share.cjs prepare <<'JSON'
   {"file":"/절대/경로/문서.md","attachments":["/절대/경로/첨부.pdf"],"editable":false}
   JSON
   ```

   `attachments`와 `editable`은 생략 가능하다. `title`, `summary`, `theme`(`light` 또는 `dark`)도 지정할 수 있다. 기존 링크를 업데이트할 때 기존 첨부는 유지하고 요청한 첨부를 추가한다.

2. 결과의 `preview.markdown`, 제목, 첨부 목록이 요청 범위와 일치하는지 확인한다. YAML 속성과 숨김 주석은 공개 본문에서 제외되지만 본문의 나머지 텍스트는 공개된다. 원본에 `publish: false`가 있으면 이를 임의로 제거하지 않는다.

3. 받은 `preparationId`와 `preview.digest`로 `publish`를 실행한다. 편집 가능 공유는 `prepare`에서 `editable:true`를 사용하고 여기에서 `pin`을 전달한다.

   ```sh
   node <스킬폴더>/scripts/obsion-share.cjs publish <<'JSON'
   {"preparationId":"준비 결과의 값","digest":"preview.digest 값","pin":"사용자가 지정한 숫자 4자리"}
   JSON
   ```

   PIN을 명령 인수, 공개 본문, 제목, 저장소 파일에 넣지 않는다. 요청 JSON은 인라인 표준 입력을 사용한다. 미리보기는 10분 동안 유효하며 원본이 달라지면 다시 준비한다. 첨부는 준비할 때의 파일 사본이다.

4. 성공 결과의 `url`을 사용자에게 전달한다. 편집 가능 공유라면 `editUrl`도 전달한다. 파일 첨부나 편집이 있으면 **Obsion 앱·PC·인터넷 연결이 유지되어야 한다**는 점을 짧게 알린다. 읽기 페이지는 앱을 닫아도 유지된다.

첨부는 파일당 5MiB, 최대 10개, 합계 10MiB이며 본문은 200KiB까지다. 공동 편집은 실제 원본 Markdown 파일을 수정한다. 공동 편집 중인 페이지를 업데이트하거나 첨부를 변경하려면 먼저 사용자가 허용한 범위에서 공동 편집을 끈다. 기존 읽기 공유를 사용자가 명시적으로 요청한 경우에만 편집 가능으로 전환한다.

## 현재 공유 중인 페이지 조회

```sh
node <스킬폴더>/scripts/obsion-share.cjs list
```

`publications`에서 제목과 `url`을 보여주고 `collaborationEnabled`로 편집 가능 여부를 표시한다. 필요하면 `updatedAt`을 사용자의 시간대로 표시한다. 공유 중지한 페이지는 포함하지 않는다. `pending:true`인 항목은 “게시 결과 확인 필요”로 구별한다. 목록이 비어 있으면 현재 공유 중인 페이지가 없다고 답한다. 조회 요청으로 새 페이지를 만들거나 암호를 변경하지 않는다. 이 목록은 **현재 기기의 Obsion이 관리하는 공유**이며 계정 전체 목록이라고 주장하지 않는다.

## 기존 링크의 암호 변경

먼저 `list`로 현재 공유를 찾는다. 사용자가 지정한 URL, 제목, 원본 경로에 해당하는 `id`를 사용한다. 여러 페이지가 일치하면 선택을 질문한다. 새 4자리 암호가 없으면 질문한다.

```sh
node <스킬폴더>/scripts/obsion-share.cjs editing <<'JSON'
{"id":"선택한 페이지 ID","enabled":true,"pin":"사용자가 요청한 새 숫자 4자리"}
JSON
```

이 동작은 기존 URL을 유지하고 새 암호를 적용한다. 기존 PIN과 참여 세션은 더 이상 사용할 수 없으므로 참여자는 새 암호로 다시 접속해야 한다. 이미 편집 가능한 페이지의 암호 변경에 문서를 다시 게시할 필요는 없다. 사용자가 편집 중지를 요청하면 같은 명령에 `enabled:false`를 전달하고 PIN은 생략한다.

## 연결과 실패 처리

앱이 꺼져 있으면 도우미가 설치 시 등록한 Obsion 앱을 실행한다. `status`로 연결 상태를 확인할 수 있다. 앱 위치가 바뀌면 `OBSION_APP`에 `.app`의 절대 경로를 지정하거나 저장소의 `npm run skill:install`로 다시 등록한다. 다른 userData를 쓰는 설치는 `OBSION_USER_DATA`로 해당 폴더를 지정한다.

게시 요청은 자동 재시도하지 않는다. 네트워크 오류나 타임아웃이면 `list`로 기록을 확인하고 공개 링크를 열람해 실제 상태를 확인한다. 오류에 `publication`이 있으면 읽기 링크 생성과 편집 설정의 부분 성공을 구별해 보고한다. 새 링크를 계속 만들지 않는다. 개인 키, 연결 토큰, PIN 해시는 출력하거나 복사하지 않는다. R2 활성화나 새 Cloudflare 계정 생성은 이 스킬의 실행 절차가 아니다.
